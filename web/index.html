ffx

Agente de código nativo, escrito em Zig, para o seu terminal.

Leve, aberto (Apache-2.0) e embutível em sistemas maiores — com skills, subagentes, servidores MCP e instruções de projeto.

Fork do fx, sem o login obrigatório

O fx exigia login com conta da Vercel para começar a usar. O ffx remove essa dependência: configure sua própria chave de API de provedor e use direto.

  • Dependência de login da Vercel removida
  • Mesmo foco em minimalismo e performance
  • Binário nativo de ~7,8 MiB
  • Skills, subagentes e MCP como no fx original

Habilidades (skills)

Uma habilidade é um diretório com um arquivo SKILL.md. O ffx descobre os metadados das habilidades na inicialização, mas carrega as instruções somente quando você ou o agente invoca aquela habilidade.

Descobrir e usar

Abra o catálogo interativo de habilidades:

/skills

Use as abas de origem e o campo de busca para filtrar. Pressione Enter para inserir a habilidade selecionada no prompt. Você também pode digitar $ no composer para buscar habilidades diretamente. Para inspecionar uma habilidade sem invocá-la:

/skills show <nome>

Onde o ffx procura

Do diretório de trabalho para cima, parando antes do diretório home:

skills/
.opencode/skills/
.codex/skills/
.claude/skills/
.agents/skills/
.claw/skills/

E então nas raízes do usuário:

~/.fx/skills/
~/.config/opencode/skills/
~/.codex/skills/
~/.claude/skills/
~/.agents/skills/
~/.claw/skills/

Instalar

Instale uma habilidade de um repositório:

/skills install vercel-labs/agent-skills --skill find-skills

Ou de um diretório local:

/skills add ./minhas-habilidades --skill minha-ferramenta

add é um alias de install. Sem --skill, o ffx instala todas as habilidades válidas da origem. Instalações gerenciadas sempre vão para ~/.fx/skills/. Use /skills path para imprimir a raiz de instalação.

Criar e remover

/skills create minha-habilidade
/skills remove minha-habilidade

Formato do arquivo

Cada habilidade usa um SKILL.md com frontmatter YAML seguido de instruções em Markdown:

---
name: minha-habilidade
description: Use isto quando uma solicitação precisar de...
---

# Minha habilidade

Instruções para o agente.

name é obrigatório e deve caber em uma linha. description é opcional. Candidatos malformados ou ilegíveis são ignorados com um aviso; as demais habilidades da mesma raiz continuam carregando.

O carregamento é explícito: descobrir uma habilidade não adiciona suas instruções a todo prompt. As instruções entram no contexto só quando a habilidade é invocada.

Subagentes

Um subagente é uma sessão filha do ffx controlada por outro agente. Ele usa o mesmo workspace e runtime, com seu próprio modelo, esforço de raciocínio, modo de permissão, transcrição e ciclo de vida.

Modos de execução

  • One-off: o filho executa um prompt e termina.
  • Persistente: retorna ao estado ocioso após cada turno e pode receber mais mensagens. Continua sendo uma sessão do ffx retomável.

Gerenciador ctrl+x

Pressione ctrl+x em uma sessão interativa para abrir o gerenciador. Com ele você pode:

  • mostrar a árvore de filhos e o estado atual;
  • criar e abrir filhos persistentes;
  • enviar instruções de acompanhamento;
  • alterar nome, modelo, esforço, modo de permissão e notificações;
  • anexar, desanexar ou reparentar uma sessão existente;
  • retomar, cancelar, fechar ou reabrir um filho;
  • resolver pedidos de aprovação do filho.

Fechar o gerenciador não interrompe os filhos persistentes.

Ferramenta do agente

O modelo usa uma ferramenta subagent com seis ramos:

RamoFinalidade
createCriar um filho one-off ou persistente.
inspectLer o estado selecionado de um filho pelo ID.
messageEnviar mensagem do pai ou emitir marco do filho.
relationshipAnexar, desanexar ou reparentar uma sessão.
configureAlterar modelo, esforço, permissões, nome ou notificações.
lifecycleRetomar, cancelar, fechar ou reabrir um filho.

Criar um filho persistente:

{
  "command": {
    "create": {
      "name": "pesquisador",
      "mode": "persistent",
      "prompt": "Inspecione o fluxo de autenticação e relate pontos de risco.",
      "model": "<provedor/id-do-modelo>",
      "effort": "high",
      "permission_mode": "ask"
    }
  }
}

As operações usam identidades duráveis, então uma nova tentativa segura retorna o resultado original em vez de repetir o efeito.

Um filho criado pelo modelo sem modo de permissão herda o modo efetivo do chamador e não pode pedir autoridade mais ampla. Um filho criado por humano no gerenciador ctrl+x pode usar a configuração explícita do gerenciador e pode adotar yolo por padrão — revise essa opção antes de iniciá-lo.

Servidores MCP

O ffx é um cliente MCP. Os servidores que você configura ficam disponíveis no shell interativo, no fx ask, em sessões ACP e para subagentes autorizados.

Configuração de perfil

O perfil privado de MCP fica em ~/.fx/mcp.json. /mcp path imprime o caminho exato:

/mcp path

O objeto raiz contém um mapa mcp. mcpServers é aceito como alias de compatibilidade, mas mcp prevalece quando ambos existem, e o ffx sempre grava mcp.

{
  "mcp": {
    "ferramentas-locais": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-everything"],
      "enabled": true
    },
    "ferramentas-remotas": {
      "type": "http",
      "url": "https://mcp.exemplo.com/mcp",
      "enabled": true
    }
  }
}

Nomes passados aos comandos MCP só podem conter letras, números, _ ou -.

Configuração de projeto e confiança

Um workspace pode fornecer configuração MCP compatível com o Claude em <workspace>/.mcp.json. O ffx a abre como arquivo regular limitado e lê apenas o objeto de topo mcpServers. Servidores de projeto começam pendentes e permanecem desconectados até você aprovar:

/mcp trust approve <nome>
/mcp trust reject <nome>
/mcp trust approve-all
/mcp trust reset

A confiança é salva em ~/.fx/settings.json sob o caminho canônico do workspace, nunca no .mcp.json. Antes da aprovação, o ffx não inicia o processo do projeto, não contata o endpoint e não carrega credenciais.

Adicionar servidores

Servidor stdio local:

/mcp add ferramentas-locais npx -y @modelcontextprotocol/server-everything

Servidor remoto (Streamable HTTP):

/mcp add --transport http prisma https://mcp.prisma.io/mcp

Depois de editar um servidor manualmente, aplique a mudança sem reiniciar:

/mcp reload

Autenticar um servidor remoto

Escolha o mecanismo mais estreito que o servidor aceita: cabeçalho estático (headers), cabeçalho secreto (header_env), token bearer (bearer_token_env) ou OAuth delegado (oauth). Um cabeçalho Authorization literal é rejeitado.

/mcp auth <nome> --open
/mcp logout <nome>

Gerenciar servidores

/mcp list
/mcp resource list <servidor>
/mcp add <nome> <comando> [args...]
/mcp add --transport http <nome> <url>
/mcp remove <nome>
/mcp reload
/mcp auth <nome> --open
/mcp logout <nome>
/mcp trust approve <nome>
/mcp path

Todas as operações também existem como comando de topo fx mcp.

Como as ferramentas chegam ao modelo

As ferramentas são descobertas de forma preguiçosa. capability_search busca habilidades instaladas e ferramentas MCP configuradas a partir de uma solicitação em linguagem natural. O modelo então chama mcp_select_tool com um resultado exato para carregar o schema executável, evitando estourar a janela de contexto. Chamadas dinâmicas de MCP usam a mesma política de permissão das ferramentas internas.

Trate a configuração do servidor como sensível: valores de ambiente do MCP podem conter credenciais, e as ferramentas do servidor executam com a autoridade que o processo ou endpoint fornece. Mantenha ~/.fx/mcp.json privado e nunca comite segredos.

Instruções de projeto (AGENTS.md)

O ffx carrega arquivos AGENTS.md como orientação de projeto. Eles podem descrever layout do repositório, comandos, convenções, requisitos de segurança e expectativas de verificação.

Origens das instruções

  • instruções globais de ~/.fx/AGENTS.md;
  • arquivos AGENTS.md do ancestor de lançamento e do workspace primário;
  • AGENTS.md mais específicos para arquivos ou diretórios alvo de uma chamada de ferramenta.

O escopo de projeto mais estreito aplicável vence em caso de conflito. Uma solicitação direta do usuário ainda tem prioridade mais alta que as instruções de projeto.

Instruções com escopo de alvo

As instruções aplicáveis não são fixas só na inicialização. Quando uma ferramenta tem um caminho como alvo, o ffx resolve a cadeia de instruções daquele alvo. Um pacote aninhado pode definir regras que valem só dentro do próprio diretório:

projeto/
├── AGENTS.md
├── apps/
│   └── web/
│       ├── AGENTS.md
│       └── src/
└── packages/

Uma chamada sob apps/web/src/ recebe os dois arquivos de projeto, com apps/web/AGENTS.md no escopo mais estreito. Defina context como false em .fx.json ou nas configurações do usuário para desativar o contexto de projeto.

Mantenha as instruções seguras para o repositório: arquivos AGENTS.md de projeto podem entrar no contexto do modelo. Não coloque credenciais, tokens privados ou dados sensíveis neles.
